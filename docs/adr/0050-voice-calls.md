# ADR 0050: Payer call workflow (E08 Voice), simulated

Status: accepted for Phase 0 (synthetic). Date: 2026-10-12.

## Context

FR07 and FR08 ask for authorized payer calls with a destination allowlist, business hours, concurrency limits and cancellation, plus fact capture with unknown and conflicting states. Docs/05 defines the deductible call flow (check status first, read back money and references, ask for the amount met before the claim rather than today's total, reconcile a dropped call before repeating a request, never fabricate a reference). Docs/06 asks for a turn-state machine with typed question-plan memory and transcript spans as locators. Docs/07 lists the call adapter contract (start, cancel, transfer, retrieve result, signed callbacks) and the telephony procurement checklist. Docs/08 requires stopping on refusal, wrong destination or unsupported identity requests, and allows human handoff and cancellation. Phase 0 has no telephony provider, BAA or customer authorization.

## Decision

1. **Durable call record in our own tables** (`server/db/050_voice_calls.sql`). `voice_calls` holds the state machine (queued, dialing, ivr, hold, transfer, rep_connected, authenticating, questioning, read_back, wrap_up, then completed, dropped, cancelled, handoff_to_human or failed), the question plan, the simulated line state and the duration counters. `voice_call_events` is an append-only, contiguous event log (states, IVR, DTMF, hold segments, agent and representative turns, verifier flags). `voice_answers` binds each extracted value to the turn sequence numbers it came from and to the read-back turn that confirmed it.
2. **One step = one transaction** with an optimistic version check. A crash mid-step rolls back completely; the step replays on restart and the simulator produces the same turns. On startup `recoverCalls` asks the adapter for each live call's line status: in progress resumes, ended is finished as dropped. A signed provider callback (`/api/webhooks/sim-voice`, HMAC over timestamp and raw body, 5-minute window, event-id dedupe, scope resolved from the provider call id) can mark a line ended while we are down.
3. **Policy gate before any dial** (`server/services/voice/policy.ts`), each refusal with a reason code: NO_PAYER_LINE, DESTINATION_NOT_ALLOWLISTED, LIVE_TELEPHONY_DISABLED, OUTSIDE_BUSINESS_HOURS (payer timezone), AUTOMATION_PAUSED, IDENTITY_UNVERIFIED or IDENTITY_CONFLICT, ACTION_IN_FLIGHT, CALL_ALREADY_ACTIVE, CONCURRENCY_LIMIT and RATE_LIMITED (per payer within a tenant), STATUS_NOT_RECENT, NO_CALL_NEEDED and DISCLOSURE_POLICY_INCOMPLETE. Client call policy is versioned, immutable data (allowlist, disclosure text, recording on/off with an all-party/one-party consent flag, verbal-reprocessing permission, status freshness, cost assumption), changed only by supervisors with a reason. Recording and consent settings are configuration only, not legal advice.
4. **Deterministic question plans** (`plan.ts`) from the account's facts that the rule does not accept (missing, conflicting or unverified), plus DED01 playbook items: claim status, accumulator confirmation before a patient-responsibility or allocation outcome, an allocation explanation, a verbal reprocessing request only when the client pre-authorized it, and the call reference. Money and alphanumeric references require read-back. A dropped call after an apparent acceptance puts a reconciliation question first, and a re-request depends on its "not found" answer. Other scenarios add a builder to `PLAYBOOKS`.
5. **Extraction without a model** (`extract.ts`). Typed parsers for amounts (digits and words, integer cents), dates (no guessed years), references (only after a cue word, never a claim number), adjustment group, crossover and turnaround (value, unit, business or calendar basis). The engine applies only the type the asked question expects. Running totals ("to date", "currently") are quarantined and never recorded as met-before. A different claim number quarantines the answer and triggers re-identification, or a handoff if it persists. Instruction-like and unsolicited text is flagged and stored, never extracted. Read-back-confirmed values become `call_transcript` evidence whose representative turns carry `extracts`, so the existing evidence, facts and DED01 pipeline resolves them as reported, or as conflicting against a disagreeing source. Unconfirmed values never become facts.
6. **Verbal acceptance is a commitment, not an outcome.** When a representative accepts a request, the open `clarify_allocation` proposal is superseded so the same request is not approved and sent again through the outbox. The account moves to `awaiting_receipt`, or to `receipt_uncertain` if the reference was never confirmed.
7. **Simulator** (`server/connectors/sim-voice.ts`): a scripted IVR, a hold queue and a representative who answers from the simulated payer's own records. It ships with a cooperative script and adversarial scripts: running total instead of met-before, refused reference, wrong claim, injection text, drop after acceptance, long hold, transfer, refusal of automated callers, and a date-of-birth request. Payer "Demo Payer A", its destination id, hours, limits and turnaround values are invented. `AR_SIM_PAYER_ALWAYS_OPEN=1` opens the synthetic line around the clock for demos.
8. **Live adapter** (`server/connectors/live-voice.ts`): the `VoiceAdapter` interface is shaped for a HIPAA-eligible provider, and `LiveTelephonyAdapter` throws `LiveExecutionDisabled` from every method. The docs/07 procurement checklist (plus counsel review from docs/08) is recorded as data, every item `not_started`.
9. **Legacy path kept.** `simulateCall` in `workflow.ts` is unchanged (the pre-scripted transcript path) so the Phase 0 tests and `npm run demo` keep their exact behaviour. The UI labels it "Pre-scripted call (legacy)". The new engine is the call path on the account page.
10. **Metrics** per call: IVR, hold and talk seconds on simulated line time, completeness (answered questions over planned questions), and a cost estimate from a per-minute rate labelled as an assumption.

## Alternatives considered

- Replacing `simulateCall` with the engine in a compatibility mode: rejected. The new gate (business hours, freshness) would make the legacy tests depend on wall-clock time, and the payload of the old path is part of the Phase 0 demo.
- A model-based extractor: out of scope and unnecessary for the simulator. The typed boundary (only the asked question's type is applied) is the containment that a future model extractor must keep.
- A workflow runtime (Temporal) for calls: still the direction in ADR 0001 for real calls. The step-per-transaction design maps to activities. This ADR does not add infrastructure.

## Blocked on real-world access

Provider selection and contract, BAA and covered-service verification, media region and retention, callback signing scheme, number registration, real speech and dialogue latency, counsel review of call law, disclosure and recording, customer authorization for live calls, payer-specific IVR trees, hours, holiday calendars and turnaround commitments, and contracted per-minute rates. None of these can be invented. Each is either config with no real values or an item on the checklist.

## Known limitations

- ~~A later re-investigation can still produce a new `clarify_allocation` proposal after a verbal acceptance.~~ Resolved by ADR 0060: the proposal can still be generated, but approval and dispatch are blocked until the verbal request is reconciled.
- Simulated time is deterministic per event and is not wall-clock time. The worker advances one step per call per tick.
- Concurrency and rate limits are counted per tenant and payer in our database, not read from a provider.
